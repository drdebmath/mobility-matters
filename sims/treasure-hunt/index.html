Treasure hunt simulator

One agent starts at node s of a graph it does not know and must reach the treasure at node v*; it recognises the treasure only when it stands on it. It runs treasure hunt by exploration sequences of doubling size (Ta-Shma & Zwick 2014): in the phases N = 1, 2, 4, 8, … it follows the exploration sequence for size N from where it stands. Entering a node by port p, with term x it leaves by port (p + x) mod deg; at the start it acts as if it had entered by port 0. Once N ≥ n, a universal exploration sequence visits every node, so the treasure is found in that phase at the latest. Real universal exploration sequences are far too long to run here: the simple example's sequences are short illustrations, and the random ones stand in for universal ones without that guarantee. A run is an illustration, not evidence for a bound.

Graph, ports and sequences

Ports follow the order of the edges: at each node, port 0 is its first edge in the list, port 1 the next, and so on. The graph must be simple and connected, with at most 100 nodes; repeated edges are merged. The treasure starts on a node farthest from the start.

Ports are numbered from 0 at each node. Default ports go counter-clockwise from the right (on the simple example, the numbers of the book's figure; on an imported graph, the order of the edge list); the adversary may number them any way, which is what Shuffle tries. Shortcuts: space plays or pauses, → makes one move.
